retro-image

画像が上から一行ずつ出てきた、あの読み込みを再現するコンポーネント。 ベースライン JPEG の走査線、GIF89a のインターレース、プログレッシブ JPEG の 3 方式を、当時のデコード順そのままに描き直す。

まずは動かす

方式を選んで再生。下のバーは実際の描画進捗。

方式

3 つを同時に走らせる

同じ画像・同じ所要時間で並走させると、それぞれのデータの届き方の違いがそのまま見える。

scanline

ベースライン JPEG / 非インターレース GIF。データがスキャンライン順に並んでいるので、届いたぶんだけ上から描くとこうなる。

interlace

GIF89a のインターレース。8 行おき → 4 行おき → 2 行おき → 残り の 4 パス。各行を次のパスが埋めるまで縦に引き伸ばすので、ブラインドが閉じるように見える。

progressive

プログレッシブ JPEG。DCT 係数が低周波から届くため、粗い全体像が先に出て、そこへ細部が乗っていく。

回線速度で待たされる

speed を指定すると、画像の実バイト数から当時の所要時間を割り出す。 実効スループットは bps / 10 で見積もっている（28.8k で約 2.8KB/s、当時の体感どおり）。

使い方

既存の <img> を包むだけ。JS が動かなければ普通の画像として出る。

<script type="module" src="/retro-image.js"></script>

<retro-image mode="interlace" duration="1400" once>
  <img src="/photo.jpg" alt="..." width="960" height="540">
</retro-image>

スクロールで一度きり再生されるだけだと見逃すので、 controls を付けると再生ボタンが生えます。属性の値がそのままラベルです。 

<retro-image mode="scanline" controls="もう一度見る">
  <img src="/photo.jpg" alt="..." width="960" height="540">
</retro-image>
属性既定意味
modeinterlacescanline / interlace / progressive
duration1400演出の長さ（ミリ秒）
speed—14.4k / 28.8k / 33.6k / 56k / isdn。指定すると duration より優先され、実バイト数から時間を算出する
max-duration8000speed 使用時の上限。長すぎる待ちを切る
bytes自動転送量を明示。未指定なら Resource Timing から取得し、取れなければ画素数から概算する
controls—再生ボタンを出す。属性の値がラベルになる（controls="もう一度見る"、省略時は Replay）
once—一度再生したらセッション中は再生しない
eager—ビューポート待ちせず即再生。既定では画面に入ってから始まる

再生の開始と終了で retro:start / retro:end が bubbles で飛ぶ。 任意のタイミングで再生したいときは要素の play() を呼ぶ。

実装で気をつけたこと

  • レイアウトを動かさない。 canvas は position: absolute で <img> に重ねるだけなので、高さを決めるのは元の img のまま。 当時さんざん画面をガタつかせた元凶が、いま CLS と呼ばれて怒られているので、そこは再現しない。
  • 別オリジンの画像でも動く。 描画は drawImage だけで完結させ、 getImageData を使っていない。canvas が tainted にならないので CORS 設定が要らない。
  • 画像が消えたままにならない。 img を隠すのは JS がそこまで到達したときだけ。 再生の完了・エラー・タイムアウトのすべてが同じ復帰処理を通る。
  • 縞の粗さは表示サイズ基準。 インターレースの 8 行おきを元画像の実ピクセルで刻むと、 いまどきの大きな画像では縞が細かすぎて見えない。当時の見た目に合わせて表示上の行で刻んでいる。
  • prefers-reduced-motion: reduce なら自動再生しない。 img に触れないので通常表示のまま出る。ユーザー自身が再生ボタンを押した場合は、意図された操作なので動く。
